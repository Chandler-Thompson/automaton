## How this works

- **One line per topic file**, in the form `- [Title](file.md) — the hook that makes
  future-me open it.` Under ~150 characters.
- **Write the topic file first, then index it.** An index entry pointing at nothing is
  worse than no entry.
- **Distill at write** — memory holds conclusions and the reasoning that earned them,
  never raw transcript. If the raw material mattered, say where it lives (floor 6
  applies to credentials: reference by location, never value).
- **Prune.** A memory contradicted by current reality is corrected or removed, not kept
  alongside. Trust what you observe now over what you remembered.
- **Seals:** a topic file marked *seal at succession* is encrypted **at write time**,
  not later. Record the mark here and the opening condition in the Charter.

## What belongs in memory

Durable things a future session cannot re-derive: who the creator is and how they
work, guidance they have given, decisions and the reasons behind them, where things
live in systems outside this repo.

## What does not

Anything the repo, the git history, or the live system answers better — file layout,
who changed what, how a bug was fixed. Ephemeral task state belongs in `mind/state/`.
People belong in `mind/rolodex/ROLODEX.md`. Acts of representation belong in the
ledger, not here.
